# COMP-04 — OpenDocs Integration Assessment

**Status:** Decision document · Recommended: Explicit integration (Phase 2)
**Priority:** P1 · Effort: S (copy/landing) + M (technical integration)
**Date:** 2026-03-30

---

## Background

OpenDocs is an open-source AI-powered documentation generator. It takes a codebase and produces or updates documentation files (README, API docs, architecture guides, etc.) using an LLM.

DocuGardener is a documentation *health monitor*. It watches repositories for drift — cases where code changes are not reflected in documentation. DocuGardener does not generate documentation from scratch.

COMP-01 assessed OpenDocs as a potential competitive overlap. This document addresses the follow-up question:

> "Is an explicit OpenDocs integration worth building? The thesis: if someone generates docs with OpenDocs, DocuGardener watches them for drift afterward. Turns a potential competitor into a top-of-funnel feeder."

---

## Relationship Analysis

### Are they competitive?

**No. They solve different problems at different points in the workflow:**

| Stage | Tool | What it does |
|---|---|---|
| 1. Doc creation | OpenDocs | Generates documentation from code |
| 2. Doc maintenance | DocuGardener | Detects when docs drift from code after changes |

OpenDocs removes the blank-page problem. DocuGardener solves the stale-docs problem. Both problems are real and independent.

A team that generates docs with OpenDocs still needs drift detection — generated docs become stale the moment the code changes.

A team that uses DocuGardener still needs to create the initial docs — DocuGardener cannot generate docs from scratch.

**Conclusion:** Complementary, not competitive.

---

## Integration Opportunity

### What an explicit integration would look like

**Level 1 — Messaging (no code required):**
- Landing page / features page: "Already using OpenDocs? DocuGardener keeps generated docs fresh automatically."
- Docs page: "Pair with OpenDocs" section explaining the combined workflow.
- README: "Recommended workflow: generate docs with OpenDocs, then add DocuGardener to your CI to detect drift."

**Level 2 — Workflow integration (S effort):**
- DocuGardener recognizes OpenDocs-generated file patterns (e.g. `docs/generated/`, OpenDocs frontmatter markers) and adjusts drift scoring:
  - Lower the noise penalty for auto-generated files (generated docs change more frequently and are expected to be regenerated).
  - Agent rule suggestion: "Auto-generated by OpenDocs — regenerate rather than hand-edit on drift."
- No special API needed — DocuGardener reads whatever files are in the repo.

**Level 3 — Direct partnership (deferred):**
- Cross-promote in each product's README and docs.
- OpenDocs provides a "Watch with DocuGardener" post-generation CTA.
- Requires ORGA-01 (public GitHub org) to be credible as an external partner.

## Risk Assessment

| Risk | Likelihood | Mitigation |
|---|---|---|
| OpenDocs pivots to include drift detection | Low | Their core value is generation; detection requires GitHub integration + RBAC + billing — not their focus |
| OpenDocs community sees DocuGardener as competing | Low | Clear messaging: "we watch what you generate" positions us as complementary, not threatening |
| Integration creates maintenance burden | Low (Level 1/2) | Level 1 is pure copy; Level 2 is a file pattern heuristic, not a hard dependency |

---

## Recommendation

**Implement Level 1 (messaging) immediately. Defer Level 2 and 3 to post-prod.**

### Actions

**Now (unblocked):**
- [ ] Add "Works with OpenDocs" note to `/docs/user-guide/repositories` page (doc paths config section — mention that OpenDocs-generated paths can be added to watch list).
- [ ] Add 1-paragraph "Pair with documentation generators" section to `/docs/user-guide/drift-detection` page.
- [ ] Add FAQ entry: "Do you work with AI documentation generators like OpenDocs?" → Yes, complementary, DocuGardener watches what generators create.

**Post-prod (after ORGA-01):**
- [ ] Reach out to OpenDocs maintainers for cross-promotion.
- [ ] Level 2: Add OpenDocs file pattern heuristics to agent rule auto-suggest.

---

## Decision

**Do not build a dedicated technical integration.** The tools are complementary by nature — no code bridge is needed. The workflow "generate with OpenDocs → watch with DocuGardener" works out of the box today. Effort is better spent on messaging (Level 1) to capture the overlapping audience.

**OpenDocs is top-of-funnel, not a threat.** Teams evaluating OpenDocs are actively thinking about documentation quality — exactly DocuGardener's audience. A clear complementary positioning converts OpenDocs awareness into DocuGardener trials.
